# 船舶影像 XAI 專案案例

## 問題與工作範圍

船舶分類模型輸出的類別分數，無法直接交代影像各處對指定類別的貢獻。本專案沿用競賽提供的 ResNet50 模型與權重，研究輸入歸因、量化解釋品質，並整理可追溯的程式、結果、交付包與發表文件。

研究與交付工作包括 Mac CPU/MPS 設備比對、固定候選的配對實驗、負面結果保存、程式與來源雜湊核對、封裝驗收，以及團隊 E017 投稿論文與簡報的文字、圖表和講稿核對。這份案例由本地報告及 v6 團隊文件整理，保留共同作者署名及實際驗證範圍。

## 兩種方法

| 項目 | Mac 4×4 遮蔽實驗 | 團隊 E017 投稿方法 |
| --- | --- | --- |
| 核心計算 | 每次遮蔽單一通道中的 4×4 tile，量測指定類別原始 logit 降幅 | 同通道以間距 16 的交錯格點分成群，固定其他群，對當前群計算部分路徑梯度 |
| 基準值 | 當前完整 CHW 輸入的最小值 | 當前完整 CHW 輸入的最小值 |
| 計算結構 | 9,408 個非重疊 tile，16 元素共同干預的降幅平均分攤回 tile | 768 群、每群 196 個特徵、4 個 Gauss–Legendre 節點；3,072 個節點樣本，每批 128 個，共 24 批 |
| 輸出整理 | 固定 soft15 後處理，保留有號歸因 | 對歸因絕對值做 Gaussian σ=1 排名，以全通道前 15% 邊界做軟閾值縮減，乘回原始有號歸因 |
| 解讀限制 | tile 分攤不能視為每個元素的精確個別干預效果 | 不同群沿不同部分路徑，不能直接沿用標準全輸入 Integrated Gradients 的完整性保證 |

## 配對實驗與結果

Mac Stage25 在同 MPS、seed42 的官方九圖上，4×4 soft15 的公式分數為 **82.65370613379287**；同設備 8×8 對照為 **78.62195221134283**，差 **+4.031753922450046**，9/9 張提高。

Stage26 使用新的 seed314159，真正執行兩法的同 MPS 完整九圖配對：4×4 soft15 為 **82.761703384019**，8×8 為 **77.155062680923**，差 **+5.606640703096**，9/9 張提高。這支持同九圖、兩個評估種子下的改善。後續 2×2 只完成一張評分，沒有 2×2 完整九圖結論。

前期也保留未過門檻的結果：Stage23 的固定 RISE 啟發候選為 74.095659，低於 8×8 的 78.621952；Stage24 的兩個固定梯度變體均未通過門檻。這些結果用於記錄研究選擇與限制。

E017 v6 團隊論文引用既有九列提交 CSV，平均 Faithfulness／Max Sensitivity／Sparsity 為 **0.612660／0.542433／0.940637**，本地公式算值為 **82.33582772987384**。它與上述 4×4 配對紀錄使用不同方法、執行來源與評估設定，分數不足以構成兩者的直接優劣比較。

目前結果來自同九張選參資料，評估種子的變更沒有增加新的影像樣本；尚缺獨立資料、物件標註與人工判讀效益驗證。

## 交付與驗收

交付流程保存程式、依賴設定、來源身份、輸出 CSV 與封裝雜湊，並核對壓縮檔完整性、manifest 的檔案集合／大小／SHA-256，以及 runner、README、Docker 配方與映像內外的一致性。

Jetson v3 與 v2 提交包的檔案與靜態核對已完成。v2 的 manifest 11/11 項大小與 SHA-256 相符；runner 修正、README 及映像內外一致性通過核對。該驗收沒有 Jetson 真機或 CUDA 執行結果，ARM64 映像交付也不能代表 Jetson GPU 全流程通過。
