# 面試展示指南

這份指南對應倉庫目前可執行的程式與保存證據。先講問題與分工，再展示程式，不必逐一翻完歷史階段文件。

## 開場

> 這個專案沿用競賽提供的 ResNet50。我這邊做的是 4×4 遮蔽實驗、結果核對，以及把程式整理成可檢查和交付的版本。團隊投稿的 E017 算法與 runner 由隊友提供，論文是共同成果。
>
> 我比較了 4×4 soft15 和 8×8 對照。同九張圖、兩個評估 seed，各提高約 4.03 和 5.61 分，兩次都是九張全部改善。這個結果在保存的資料和設定下成立，還不能說明新影像的表現。

## 現場指令

先依 [README](../README.md#執行示範) 裝好環境，面試時從倉庫根目錄執行：

```bash
python tools/interview_demo.py
```

第一段是**本次 CPU 合成測試**。固定線性模型的最高分類別是 4，但解釋目標是 0 和 2；程式直接核對這兩個目標的解析歸因，並檢查 FP32、輸出形狀、正負值及輸入／亂數狀態。

第二段是**保存的 Mac MPS 結果重算**。程式讀取四份 CSV，重新計算兩個 seed 的對照、候選、分數差與改善張數，並核對 README。它沒有載入官方模型、競賽影像或重跑九圖。

要看完整檢查項目，可執行 `python tools/interview_demo.py --json`。交付檢查可另外執行：

```bash
python tools/jetson_audit/test_tools.py -v
```

面試現場不必安裝套件、建 Docker 或跑完整九圖。若環境臨時有問題，README 的圖、保存 CSV 與原始碼仍可用來說明；不要把保存結果說成剛剛完成的實驗。

## 實作說明

每次只遮蔽一個通道中的 4×4 區塊，以當張圖完整 CHW 的最小值替代。計算指定類別在遮蔽前後的 logit 差，除以 16，平均分回區塊。遮蔽後分數上升時，歸因會是負值。

soft15 先對歸因絕對值做空間平滑，平滑不跨通道；再以整張 CHW 的 85% 分位數作共同門檻，將連續縮減係數乘回有號歸因。這是固定的後處理選擇，尚缺獨立資料集確認。

### 一個實際的驗收問題

隊友交付包原本將 `Max_Sensitivity` 限制在 [0, 2]，但 scorer 接受大於 2 的有限值，只將該項得分截為 0。兩邊對合法輸入的定義不同，可能阻擋新資料輸出。

本倉庫的工作是定位差異、建立驗收工具，並用 34 個 admission 案例和 5 個 scorer 案例核對隊友修正版。這些是歷史合成測試紀錄，不是 Jetson 推論結果。公開倉庫可以跑的小型工具測試另有 8 項，未提供的原交付包不會被當成已重跑。

## 常見追問

| 問題 | 可以依證據回答的內容 |
|---|---|
| 為什麼選 4×4？ | 4×4＋soft15 整體方案在兩組配對比較較好。2×2 的遮蔽數再增加四倍，目前只完成單圖，沒有完整九圖結論。 |
| 改善全來自區塊變小嗎？ | 不能這樣下結論，對照與候選的後處理也不同。Stage25 同 4×4 下比較了 post22 與 soft15，但這還不是完整因子消融。 |
| 為什麼保留負值？ | 遮蔽後指定類別的分數可能上升，logit drop 因此為負。這是相對該遮蔽基準的模型行為，不能直接解讀成現實物件的負面意義。 |
| 兩個 seed 能證明泛化嗎？ | 不能，影像仍是同九張。第二個 seed 只增加評估設定的確認。 |
| 如何避免解釋錯類別？ | 固定線性模型的 argmax 是 4，指定 targets 是 0、2，再直接比較這兩類的解析歸因答案。 |
| 快取會不會拿到舊答案？ | runtime 快取只存在當次記憶體，識別完整輸入、target、model state、device 與方法設定，預設最多六筆。計算這些識別資訊也有成本。 |
| ARM64 Docker 通過就能在 Jetson 跑嗎？ | 不能這樣推論。已有 ARM64 CPU 原生 VM、AMD64 模擬與 save／load／smoke 紀錄；CUDA、ABI、記憶體和速度仍須實機確認。 |
| E017 是你的 4×4 方法嗎？ | 兩者不同。E017 算法與 runner 由隊友提供；4×4 遮蔽、配對實驗、CPU 部署和獨立驗收分開記錄。 |
| 下一步先做什麼？ | 補獨立影像集，確認 soft15 的選擇；再做 CPU 完整九圖複評與 Jetson GPU 實機驗證。 |

## 履歷描述

- 實作單通道 4×4 遮蔽與 soft15 歸因；固定九圖、兩個評估 seed 的 Mac MPS 配對實驗，較 8×8 對照分別提高 4.03 與 5.61 分。
- 整理 Linux ARM64／AMD64 CPU Docker 流程，保存來源 SHA-256、依賴版本與 save／load／smoke 紀錄。
- 建立 CSV、manifest 與 Docker／OCI 映像檢查工具，定位 sensitivity 上界與 scorer 不一致的缺陷，驗證隊友修正版。

使用時按實際分工說明。模型訓練、E017 算法原創、正式競賽排名及 Jetson GPU 效能未列入個人成果。
