## 唯一新候選：`black_occlusion8_signed`

以第 21 階段 `experiment.py` 的遮蔽核心為起點，**只預先固定一個 8×8 方案**；不因九張分數臨時調整 tile、stride、符號或後處理。對每個當前 NCHW `float32` 圖片 `x` 與其傳入的目標 `y`，取**完整三通道 CHW 最小 scalar** `b=min(x)`，用 `model.eval()`、`torch.no_grad()` 算目標 **logit** `z=model(x)[y]`。當 Quantus 傳來微擾輸入，須對該微擾圖重新算 `b`、`z` 及全部歸因，不能沿用原圖分片。

三通道各切成 28×28 個**不重疊 8×8** tile，合計 **2,352** 塊。每次只遮蔽一個通道的一個 tile：該 tile 的 64 個 CHW 值替換成自己的 `b`，其餘位元組不變；將帶符號的 `r=(z−z_mask)/64` 回填此 tile。照第 21 階段相同規則，依 `abs(r)` 保留完整 CHW 前 25% 且維持符號 → 各通道 reflect padding 的 5×5 算術平均 → 依絕對值保留完整 CHW 前 10% 且維持符號。沒有 SmoothGrad；返回與輸入同 shape 的有限 `float32`。只支援這輪的 3×224×224，其他尺寸明確報錯。評估 seed **42**、CPU、batch size 1、`shuffle=False`，原版 `generate_xai_submission` 與原版 `metrix.py`／`score_c3.py`，不能修改官方指標與模型。

此法測試粒度從 256 縮到 64 個 CHW 元素是否改善官方 Faithfulness 隨機抽取 50 個**分散元素**時的關聯。64 是單個連續 tile 的大小，**不等於**官方一次擾動 50 個分散元素；8×8 是否有幫助只能以實測判斷。預估 54 個不同輸入各 2,352 個遮蔽輸入，共 **127,008** 個，約前輪四倍、可能需數小時；記錄實測時間和記憶體，不保證四倍精確。Mac 若資源允許可沿用 8 執行緒、推論 batch 32；調整推論 batch 須驗證同一 tile 的 logit／r 在容許浮點誤差內一致，且不得改算法。
